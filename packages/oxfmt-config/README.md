# @taiki-kuraishi/oxfmt-config

SKILL の規約を表す oxfmt の共有設定。

## 責務

- 実装すること: kstack の SKILL ごとの oxfmt 設定オブジェクト（利用側の `oxfmt.config.ts` で spread する）
- 実装しないこと: oxlint の設定・ルール、SKILL に書かれていない整形の好み

## SKILL と設定の対応

export する設定は SKILL の名前から `kstack-` を除いた名前にする。oxfmt の設定は整形の選択肢しか持たないので、整形の好みを決める規約だけが対象になる。

### kstack-typescript

oxfmt で表せる規約は無い。`if` の前の空行も、oxfmt が既存の空行を保つだけで挿入しないため、`@taiki-kuraishi/oxlint-config` の `kstack/blank-line-before-if` で検出する。

| 規約                                                           | 設定 / 表せない理由                                                                                      |
| -------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------- |
| 導出できる型を手書きしない                                     | 表せない。oxfmt は型アノテーションを足し引きしない                                                       |
| else・三項演算子を使わない。早期 return する                   | 表せない。oxfmt は制御構造を書き換えない                                                                 |
| `if` の前には空行を置く                                        | 表せない。oxfmt は既存の空行を保つだけで挿入しない（oxlint の `kstack/blank-line-before-if` で検出する） |
| 関数の引数はオブジェクトに構造化する                           | 表せない。oxfmt は引数の形を変えない                                                                     |
| 条件付きオブジェクト spread を使わない                         | 表せない。oxfmt は式を書き換えない                                                                       |
| 小さすぎる処理を関数化しない                                   | 表せない。関数の分け方は整形の選択肢に無い                                                               |
| 各メソッドで繰り返す依存の生成は constructor に置く            | 表せない。コードの置き場所は整形の選択肢に無い                                                           |
| 型の絞り込みのためだけに this のプロパティを分割代入しない     | 表せない。oxfmt は分割代入を書き換えない                                                                 |
| class でしか使わない関数は private method にする               | 表せない。コードの置き場所は整形の選択肢に無い                                                           |
| class・error・定数・型が同居するファイルはディレクトリに分ける | 表せない。oxfmt はファイルを分けない                                                                     |

### kstack-layerd-architecture

oxfmt で表せる規約は無い。step 番号付きの doc と `// Step N:` コメントは oxfmt が整形するだけで、doc と本文の対応は変えられない。doc の step の有無と本文との対応は `@taiki-kuraishi/oxlint-config` の `layerdArchitecture`（`kstack/use-case-steps`）で検出する。

| 規約                                                         | 設定 / 表せない理由                                                 |
| ------------------------------------------------------------ | ------------------------------------------------------------------- |
| 層のファイルは class で書き、モジュール直下に関数を置かない  | 表せない。コードの置き場所は整形の選択肢に無い                      |
| client は外部サービスとの境界を閉じる                        | 表せない。引数と method の分け方は整形の選択肢に無い                |
| repository は 1 table 1 class、1 query 1 method              | 表せない。class と method の分け方は整形の選択肢に無い              |
| use case は execute だけを持ち、分岐と呼び出しだけを書く     | 表せない。method の分け方は整形の選択肢に無い                       |
| use case の処理は step 番号付きの doc と step コメントで書く | 表せない。oxfmt はコメントを書き足さず、step の間の空行も挿入しない |
| service・utils・libs は最後の手段                            | 表せない。ファイルの置き場所は整形の選択肢に無い                    |

### kstack-monorepo

oxfmt で表せる規約は無い。README の規約は kstack-readme に移した。

| 規約                                        | 設定 / 表せない理由                                      |
| ------------------------------------------- | -------------------------------------------------------- |
| 責務に合わない処理は package を新設して置く | 表せない。コードとファイルの置き場所は整形の選択肢に無い |

### kstack-readme

oxfmt で表せる規約は無い。Markdown は整形の選択肢しか持たず、README に何を書くかと書く言語は決められない（root README の Bad / Good に `oxfmt --check` は差分を出さない）。

| 規約                                                                               | 設定 / 表せない理由                    |
| ---------------------------------------------------------------------------------- | -------------------------------------- |
| root README には名前・概要・使い方の入口・license だけを書く                       | 表せない。oxfmt は節を足し引きしない   |
| package の README に責務 section を置く                                            | 表せない。oxfmt は節を書き足さない     |
| package の README には使い方・セットアップ・テスト手順を書き、実装の詳細は書かない | 表せない。oxfmt は節を足し引きしない   |
| agent 向けの指示と、すぐ古くなる数値・一覧を書かない                               | 表せない。oxfmt は文を削除しない       |
| 日本語で書き、upstream から取り込んだ README は原文のまま残す                      | 表せない。oxfmt は文章の言語を変えない |

### kstack-gdscript

oxfmt で表せる規約は無い。`.gd` は oxfmt の整形対象ではない（`oxfmt --check src/player.gd` は `Expected at least one target file` になる）。

### kstack-code-comment

oxfmt で表せる規約は無い。oxfmt はコメントを整形するだけで、書き足しも削除もしない。例外の列挙を広げた変更には、新しい規約は無い。

| 規約                                              | 設定 / 表せない理由                                           |
| ------------------------------------------------- | ------------------------------------------------------------- |
| コメントにコードの what を書かない                | 表せない。oxfmt はコメントを削除しない                        |
| class の method と export する関数には doc を書く | 表せない。oxfmt は doc と `// Step N:` コメントを書き足さない |
| 理由の形をした what も書かない                    | 表せない。oxfmt はコメントを削除しない                        |
| 複製元のコメントを引き継がない                    | 表せない。oxfmt はコメントを削除しない                        |

### kstack-better-result

oxfmt で表せる規約は無い。

| 規約                                                          | 設定 / 表せない理由                                                             |
| ------------------------------------------------------------- | ------------------------------------------------------------------------------- |
| 複数の fallible なステップは Result.gen に繋げる              | 表せない。処理の組み立て方は整形の選択肢に無い                                  |
| Result.gen の規則                                             | 表せない。oxfmt は `yield`・`return` の式を書き換えない                         |
| Result.gen のステップと分岐は空行で区切り、意図をコメントする | 表せない。oxfmt は既存の空行を保つだけで挿入せず、コメントも書き足さない        |
| 単一ステップは map / andThen で十分                           | 表せない。処理の組み立て方は整形の選択肢に無い                                  |
| Result.tryPromise には処理を 1 つだけ書く                     | 表せない。oxfmt は `try` の中身を分けない                                       |
| 扱いを変える失敗は、返す時点で別の TaggedError にする         | 表せない。エラーの定義は整形の選択肢に無い                                      |
| 失敗を null / undefined で返さず、Result の Err で返す        | 表せない。失敗を `null` で返すか `Result` の `Err` で返すかは整形の選択肢に無い |

### kstack-git

oxfmt で表せる規約は無い。`.gitignore` は oxfmt の整形対象ではない（`oxfmt --check .gitignore` は `Expected at least one target file` になる）。

| 規約                                    | 設定 / 表せない理由                                                                                |
| --------------------------------------- | -------------------------------------------------------------------------------------------------- |
| .gitignore は repo root に 1 つだけ置く | 表せない。`.gitignore` は整形対象ではなく、ファイルの置き場所も整形の選択肢に無い                  |
| commit の書き方                         | 表せない。commit message と stage する範囲は整形対象のファイルに現れない                           |
| PR の作り方                             | 表せない。PR の title・body・assignee と作成後の subagent による確認は整形対象のファイルに現れない |
| PR を merge する                        | 表せない。merge の判断と CI・approve の確認は整形対象のファイルに現れない                          |

### kstack-rest-api

oxfmt で表せる規約は無い。整形の選択肢しか持たず、route が返すリソースの範囲、URL の形、request の値をどこで変換するかは決められない（3 規約の Bad / Good に `oxfmt --check` は差分を出さない）。

### kstack-testing

oxfmt で表せる規約は無い。整形の選択肢しか持たず、Arrange / Act / Assert のコメントの有無、テストデータをどこで作るか、テストの本数と assert に何を書くか、`it` / `test` の名前と `describe` の名前の言語は決められない（6 規約の Bad / Good に `oxfmt --check` は差分を出さない）。

### kstack-playwright

oxfmt で表せる規約は無い。整形の選択肢しか持たず、テストの置き場所、Docker で実行するか、テスト名の言語とコメント、1 ケースの粒度は決められない（4 規約の Bad / Good に `oxfmt --check` は差分を出さない）。VRT のテスト名は `@taiki-kuraishi/oxlint-config` の `playwright`（`kstack/vrt-test-name`）で検出する。

### kstack-drizzle-orm

oxfmt で表せる規約は無い。

| 規約                                                           | 設定 / 表せない理由                                                                                                                                                                                              |
| -------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| Relational Queries では drizzle-orm から演算子を import しない | 表せない。oxfmt は import と `where` の書き方を変えない                                                                                                                                                          |
| 親を消すときの子の行は、外部キーの onDelete で DB に消させる   | 表せない。子の行を誰が消すか、cascade にするかの確認、migration の SQL を読む手順は整形の選択肢に無い。`.sql` は oxfmt の整形対象ではない（`oxfmt --check m.sql` は `Expected at least one target file` になる） |
| テストでは drizzle の client を in-memory DB に差し替える      | 表せない。テストの DB の用意の仕方は整形の選択肢に無い                                                                                                                                                           |

### kstack-agents-md

oxfmt で表せる規約は無い。

| 規約                                                       | 設定 / 表せない理由                                                                                                  |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------- |
| 実装の事実ではなく、コードに現れないリポジトリの規約を書く | 表せない。Markdown は整形の選択肢しか持たず、何を書くかは決められない                                                |
| 日本語で書き、upstream から取り込んだものは原文のまま残す  | 表せない。oxfmt は文章の言語を変えない（英語の Bad と日本語の Good の Markdown に `oxfmt --check` は差分を出さない） |
