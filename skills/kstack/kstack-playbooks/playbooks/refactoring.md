# リファクタリング

**持つもの: 振る舞いを固定したまま、構造を変えるところまで。**

使う場面: 振る舞いを変えずに、コードの構造（関数・ファイル・層の分け方、名前、重複）だけを変える。振る舞いとは、API の入出力、画面の表示と操作、DB に書くもの、外に出すログやイベントをいう。画面の見た目を変えずに実装を移すときは、見た目を合わせる playbook を使う。package の外から使われる型や関数の形を変える設計の変更は、振り分け表の「どれにも当たらない」に回す。途中で不具合や足りない機能が見つかったら、このリファクタリングには入れず、別の依頼として振り分け直す。

1. 振る舞いを固定する。対象を使う側から辿って今の振る舞いを書き出し、それを守るテストがあるかを見る。無ければ、今の振る舞いをそのまま期待値にしたテストか snapshot を先に足す（書き方は `kstack-testing`）。型検査と lint は固定にしない。完了条件: 変える範囲の振る舞いごとに、今のコードで通るテストがある
2. 目指す形を書く。今作るならどう分けるか（ファイル、型、呼び出しの向き）を、`kstack-layerd-architecture`・`kstack-monorepo` など対象の SKILL に合わせて書く。分岐や無効な状態が減らず、間接層が増えるだけの形なら、やめて報告する。完了条件: 目指す形と、それで消えるもの（分岐、重複、呼び出し元の数）が書けている
3. 足す前に消す。使われていないコード、呼び出し元が 1 つの wrapper、重複した検証を先に消す。完了条件: 消したものごとに、手順 1 のテストが通る
4. 小さく動かす。1 回の変更ごとに手順 1 のテストを流す。package の中の型や関数の形を変えるときは、呼び出し元をすべて移し、古いものを同じ変更で消す。互換のための shim や、新旧を並べた経路は残さない。名前を変えたら、LSP の参照と文字列・文書での出現を grep で確かめる。完了条件: すべての呼び出し元が新しい形を使い、古い形への参照が 0 件
5. 振る舞いが変わっていないことを実物で確かめる。手順 1 のテストに加え、変更が大きいときは、新旧の出力を比べる script を流すか、dev server・CLI で同じ操作をして比べる。完了条件: 比べた出力が一致している
6. 残す価値を確かめる。読む人が追う関数・ファイル・分岐が減っていなければ、変更を戻す
7. commit は、消す変更、形を変える変更、後片付けの順に分ける

```text
Bad: 型検査が通ったので、テストの無い関数を分割して完了とする / 新旧の関数を並べて、呼び出し元の移行は後回しにする
Good: 今の出力を期待値にしたテストを先に足し、分割の各段でそれが通ることを確かめ、古い関数を同じ変更で消す
```

なぜ: 振る舞いを固定してから動かさないと、壊したことに気づけない。古い形を残すと、読む人は新旧どちらが正しいかを毎回確かめることになる。

**報告**: 変えた構造（前と後）、振る舞いを固定したテスト、一致を確かめた方法と出力、消したもの、戻したもの。
