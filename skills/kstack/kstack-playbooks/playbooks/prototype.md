# 試作

**持つもの: 設計の判断まで。試作のコードは使い捨てる。**

使う場面: 画面の配置や操作、処理の方式やタイミングのように、作って見ないと選べない案を比べて決める。決めることが無ければ試作しない。決めた案を本番のコードにするのは、画面・API などの playbook で別に回す。

1. 試作で決めることを 1 つにする（どの配置か、どの方式か）。完了条件: 決めることが 1 文で書けている
2. 方向が決まっていなければ、似た既存の画面・事例を集めて方向を選んでもらう。agent-mode は `kstack-playbooks` の「playbook の回し方」の手順 2 で user に聞き、bot-mode は方向ごとの案を手順 4 の切り替えに並べ、手順 6 の通知で選んでもらう。方向が決まっていれば飛ばす
3. 本番のコードとは別の、commit しない場所（repo の外の一時ディレクトリ）に作る。画面なら素の HTML・CSS・JS か一番軽い構成、処理なら問いを確かめる最小の script にする。本番の framework、テスト、抽象は入れない
4. 案を比べるときは、1 つの試作の中でボタンかキーで切り替えられるようにし、各案に名前を付ける
5. 実物で確かめる。画面なら案ごとに screenshot を撮って操作し、処理なら出力やタイミングを記録する。完了条件: 案ごとの screenshot か出力がある
6. 案、得るもの・代償、おすすめを返す。好みで決まる選択は user に残す。試作は repo のコードも文書も変えないので、bot でも bot-driven のフェーズや PR にせず、依頼元への最後の通知に結果を添える

```text
Bad: 試作をそのまま本番の画面に組み込んで PR を出す / 案を 1 つだけ作って「これで良いか」と聞く
Good: 3 つの配置を 1 つの HTML で切り替えられるようにし、screenshot を並べておすすめを添え、選ばれた案を画面の playbook で作る
```

なぜ: 試作の目的は、安く作って比べて捨てることである。本番の品質で作ると比べる案の数が減り、そのまま本番に入れると、試作の近道がコードに残る。

**報告**: 決めたこと、比べた案、案ごとの screenshot か出力、おすすめ、試作の場所。試作は使い捨てで、本番のコードではないと書く。
