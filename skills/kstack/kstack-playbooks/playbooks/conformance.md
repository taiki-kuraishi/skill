# 規約・文書のずれを直す

**持つもの: 指摘ごとの修正。文書と実装のどちらに合わせるかの判断は持たない。**

使う場面: コードを kstack SKILL の規約に、文書（AGENTS.md・README・docs/・コメント）を実装に合わせる。`kstack-skill-review`・`kstack-drift-review` の指摘を直す依頼も含む。

1. 指摘を用意する。指摘を渡されていればそれを使い、無ければ対象の範囲で `kstack-skill-review` と `kstack-drift-review` を subagent で並行に回す。完了条件: 直す対象の指摘が一覧になっている
2. 指摘を分ける
   - 直す: skill-review の「違反」、drift-review の「文書が古い」
   - user に聞く: どちらの review の「要確認」も、skill-review の SKILL 同士が食い違う箇所、drift-review の「実装が外れた」「判断が要る」
   - 「既存」に分けられた指摘は直さず、報告に残す
3. 直す指摘を、根拠の規約の Good の形にする。挙動が変わり得る修正は、前後で動きが同じことを subagent に確かめさせる
4. 聞く指摘は、`kstack-playbooks` の「playbook の回し方」の手順 2 で聞く

```text
Bad: 「実装が外れた」のドリフトを、文書に合わせてコードを書き換えて直す
Good: 「文書が古い」だけを直し、「実装が外れた」はどちらに合わせるかを user に聞く
```

なぜ: 違反と古い文書は、正しい形が SKILL と実装で決まっている。実装が文書から外れたときは、どちらが正しいかがどこにも書かれていない。

**報告**: 直した指摘（根拠の SKILL と見出し、または文書と実装の箇所）と、聞いたことと答え。
