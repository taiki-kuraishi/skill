# 見た目を合わせる

**持つもの: 基準の screenshot との差分が 0 になるまで。**

使う場面: 既にある画面の見た目を変えずに実装を移す（UI ライブラリの移行、component の作り直し）、または既にある画面を既存の見た目（デザインのモック、別の実装の画面）にピクセル単位で合わせる。まだ無い画面をモックから作る依頼と、見た目そのものを変える依頼は、画面の playbook で扱う。

1. 基準を作る。移す前の画面（モックに合わせるときはモック）を、`kstack-playwright` の VRT で表示状態ごとに撮り、基準の screenshot にする。基準を撮れないときは、ここで止まって報告する。完了条件: 対象の表示状態ごとに、基準の screenshot と、今の実装で通る（モックに合わせるときは落ちる）VRT がある
2. 近道をしない。基準の screenshot と、VRT の harness・設定（閾値を含む）は変えない。差分を消すために、component の見た目を基準から外す変更もしない。基準が誤っていると思ったら、直さずに `kstack-playbooks` の「playbook の回し方」の手順 2 で聞く
3. 1 つずつ移す。共通の部品（ボタン、色や余白の token）を先に移し、そのあと component か画面を 1 つずつ移す
4. 移すたびに VRT を流し、差分が 0 になるまで直す。差分が出たら、差分の画像で場所を確かめてから直す。目で見て「同じ」は確認にしない。完了条件: 移した component の VRT がすべて差分 0 で通る
5. commit と PR は、読み込んだ mode の決まりで component ごとか、まとめて安全な単位で出す

```text
Bad: 差分が 1% 残ったので、VRT の閾値を上げて通す / 基準の screenshot を撮り直して差分を消す
Good: 差分の画像で余白のずれを見つけて直し、閾値を変えずに差分 0 で通す
```

なぜ: 見た目を合わせる作業の正解は基準の screenshot だけである。基準や閾値を動かすと、どこまで合ったかを誰も言えなくなる。

**報告**: 移した component、それぞれの VRT の結果、基準の screenshot の場所、残っているもの。
